01 / overview

The problem

Every keystroke in the editor waited for a server round trip. On a good connection that was fine; on hotel Wi-Fi it made the product feel broken, and it was the top complaint in support tickets.

I led the rebuild of the sync layer so that edits apply locally first and reconcile in the background, without changing the editor's API for the rest of the team.

02 / my contribution

What I did

  1. 01Designed the operation log and merge rules, and wrote the RFC the team built from.
  2. 02Built the client sync queue on SQLite (WASM) with retry, backoff and offline support.
  3. 03Wrote a property-based test suite that replays thousands of random edit interleavings.
  4. 04Ran the rollout behind a flag: 5%, 25%, 100% over three weeks, with no rollbacks.

03 / decisions

Key decisions

Decision 01

Operation log over CRDT library

We kept our own small op log instead of adopting a full CRDT library. Our documents are mostly append-only, so the simpler model was easier to reason about and 10× smaller.

Decision 02

SQLite in the browser

Local storage needed transactions and real queries. SQLite on OPFS gave us both, and the same schema runs on the server.

Decision 03

Measure what people feel

We tracked time from keypress to paint, not API latency, so the number we optimised was the one users noticed.
